# OPNsense ruleset spec — DRAFT v0.1 (for review with Network)

Source: "How the Competition Works" draft 0.1 (9 Oct 2026), sections 5, 6.3 and 8.
Principle: default-deny everywhere, rules generated from the database (make-scope.py), never hand-edited during a round.

## 1. Where rules live (check this first)
- Participants reach the gateway on **UDP 51820 only**. That is a rule on each participant VLAN / Teams interface.
- Once inside the tunnel, traffic arrives on the **WireGuard interface (or interface group)**, not on the VLAN interface. Scope rules (Red to app, Blue to app) belong on the WireGuard interface/group. Confirm with Network which one is used.
- Each WireGuard peer's server-side **AllowedIPs must be exactly its own /32**. This is what stops one person sending as another.

## 4. Kill switch
- Rule 0 must be a **floating quick rule** at the top, in both directions, and tied to the group RED_ALL.
- Toggling the rule alone does **not** cut sessions already open. After enabling, **kill states** for RED_ALL ranges.
- Restore: disable rule 0, no state action needed.
- Two named owners (names in the access register). Target: traffic cut in under 10 seconds.
- API route (verify exact endpoint names in your OPNsense version's API docs before scripting):
  toggle the rule by UUID, apply the changes, then call the firewall state-kill endpoint.
  Use a dedicated API user with only these permissions.

## 5. Access to the firewall itself
- Named admin accounts only; GUI/SSH reachable from Staff VLAN 102 / Mgmt 101 only.
- SSH keys, no password login, no root login.
- The shared bootstrap login is disabled before the event.
- API user "provisioning" for make-wg-peers.py / make-scope.py: minimal permissions, source-restricted to 10.109.0.20 (shared VM).
